# 本机持久化与启动

## 启动

双击项目根目录的 `启动婚礼筹备.command`，或在该目录运行 `npm run start:local`。入口固定使用 `http://127.0.0.1:3010`。如果服务已启动，就直接打开；否则先构建，再在后台运行生产服务。需要 Node.js 22.13 或更新版本及已安装的项目依赖。

电脑重启后再次双击启动即可。无需重新导入项目，没有设置开机自动启动。日志位于 `.local/server.log`。

## 数据文件

- `.local/wedding.sqlite`：任务、图片、预算及婚期的主数据库。
- `.local/wedding.sqlite-wal` / `-shm`：SQLite 运行时文件，不要在服务运行时手动删除。
- `.local/backups/project-*.json`：自动生成的完整项目快照，保留最近 30 份。
- `.local/ai-config.json`：服务端 AI 模型配置。
- `.local/chats.sqlite`：聊天会话、消息与建议任务处理标记；同样可能带有 `-wal`、`-shm` 运行时文件。

数据与构建目录独立，重新构建或重启服务不会清空数据库。迁移时先停止服务，再保留并移动整个 `.local` 目录。主题、界面偏好仍是浏览器本地设置；AI 对话已持久保存，撤销历史仍只在当前页面内。项目 JSON 快照不包含聊天记录和模型配置。

## 首次迁移

在原来使用的浏览器环境中刷新页面。当 SQLite 中还没有项目时，自动读取 IndexedDB 或旧 localStorage 项目并写入数据库；原浏览器记录不删除。页面显示“已保存到本机数据库”后，再用其他浏览器访问同一服务，也能打开同一项目。

服务器已有项目时以数据库为准，不使用另一个浏览器里的旧缓存覆盖它。如需替换项目，使用已有的 JSON 备份导入功能。多个页面同时编辑有版本冲突时会拒绝覆盖：先保存当前任务表记录，再刷新获取最新版本。

## 自动备份与恢复

每次实际修改写入数据库前，保存上一版本 JSON 快照；首次写入备份初始项目。重复保存相同内容不会新增快照。备份失败时拒绝写入，避免没有历史副本的覆盖。

需要恢复时，在页面点击“导入备份”，选择 `.local/backups` 中的 JSON 文件并确认。导入过程本身也会备份替换前的数据。删除任务后应及时恢复，连续修改超过 30 次可能淘汰更早的快照。

本机自动备份不能防止整台电脑磁盘损坏或目录被删除，重要阶段仍建议把导出文件另存到其他磁盘。
