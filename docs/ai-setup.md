# AI 助手配置

顶部星光按钮打开对话面板，可评审当前进展或生成新增任务建议。任务建议默认不选中，需勾选并点击“确认加入”后才写入项目，可使用现有撤销操作撤回。

## 在页面中设置

打开 AI 对话框，点击右上方的齿轮，或从项目设置进入“AI 模型设置”。

1. 选择 OpenAI、DeepSeek、通义千问或自定义兼容接口。
2. 核对接口地址和模型名称，填写对应服务商的 API Key。
3. 点击“测试并保存”。服务端发出一次简短模型请求验证连接和 JSON 回复能力，不发送婚礼任务。
4. 验证成功后保存并关闭设置窗口，无需重启；失败时保留输入和原配置。

已有密钥不会回显；同一服务商和接口地址下留空可保留旧密钥。更换服务商或地址需要重新填写。配置保存在服务端 `.local/ai-config.json`，文件权限为仅当前用户可读写，已排除版本管理。该文件为本机明文配置，不是加密密钥库。

## 环境变量方式

未通过页面保存配置时，也可以在项目根目录的 `.env.local` 配置以下服务端变量，然后重启开发服务。页面保存的配置优先于环境变量。

```dotenv
AI_API_KEY=你的密钥
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=gpt-4.1-mini
```

兼容提供 `/chat/completions` 且支持 `response_format: json_object` 的服务。`AI_BASE_URL` 应包含版本前缀，例如 `/v1`，不包含 `/chat/completions`。

密钥不会返回浏览器。发送的上下文包括项目名称、婚期、预算和任务文本信息，不包含图片。AI 回复仅生成建议，不直接删除或修改原任务。父分支和日期会校验，相同父节点下同名任务不会重复创建。一次最多加入 30 条建议，整个项目上限 500 个任务。

## 流式回复与历史

服务端使用 `stream: true` 请求模型，通过 SSE 把回复正文逐段传给页面。正文实时渲染 Markdown，任务链接可定位画布。任务建议和后续提问在完整 JSON 校验通过后显示，生成中不会自动增加任务。兼容接口若仍返回完整 JSON，则在响应结束后一次显示。

接口返回的 `reasoning_content` 或字符串类型 `reasoning` 会显示在“思考过程”区域；生成中默认展开，结束后默认收起，可点击切换。该区域只显示接口实际提供的内容，不会为普通模型生成虚假的思考过程。每次最多保留 32,000 字符的思考内容。

聊天、思考内容和建议处理记录保存在本地 SQLite 中，可从会话列表续聊。每个会话还保存阶段摘要和长期记忆（婚期、预算、偏好、已确认决策），记忆面板可以手动编辑。模型每轮只返回本轮摘要和新增事实，客户端合并后保存；中断、超时或格式错误时不更新记忆。下一轮发送最新项目数据、长期记忆、阶段摘要，以及最近至多 12 条、合计至多 24,000 字符的正文消息，优先保留最新问题、按完整消息裁剪旧对话，不发送思考内容和已中断的 AI 回答。裁剪只影响模型请求，本地聊天历史不删减。刷新前已经完成保存的聊天可以恢复；正在生成的内容若直接刷新页面，尚未保存的片段可能丢失。

## 超时与中断排查

单次生成最长等待 10 分钟；从发起上游请求开始，连续 120 秒没有收到上游数据才按无响应超时处理。思考内容、正文、上游心跳都会刷新无响应计时，即使思考内容已超过显示上限也会继续等待正文。服务端每 15 秒向页面发送保活注释，这些注释不会延长上游无响应时限。接口返回 `finish_reason: stop` 后直接校验结果，不再等待可选的 `[DONE]` 标记。

提示分别区分无响应超时、总时限、连接中断、模型输出长度上限、无效流数据和任务协议校验失败。遇到错误时保留已收到的内容并暂停等待队列，原问题回填输入框，可手动重试；未通过校验的任务和画布变更不会执行。模型自身的输出上限、服务商限流或代理断线仍需根据具体提示处理。

每次请求结束会输出一条 `[ai]` 诊断日志，包含请求编号、耗时、上游 HTTP 状态、结束原因码、接收字节数和上下文长度；不记录密钥、接口地址、聊天内容或思考正文。用固定启动入口运行时可在 `.local/server.log` 查看；开发模式则看终端输出。

此应用目前面向本机使用；对外部署前应增加用户认证和请求限流。
